# 字间 · 文章排版工作台

为个人使用的文章自动排版工具。导入 Word 或粘贴文章后自动美化，选择主题，复制图文或通过文章同步助手保存到微信公众号草稿箱。

## 启动

需要 Node.js 20.19+ 或 22.12+，建议使用 Chrome / Edge。

```powershell
npm.cmd install
npm.cmd run dev
```

打开终端显示的本地地址，默认是 <http://127.0.0.1:5173>。Windows 也可以双击根目录的 `启动字间.cmd`，首次运行会安装依赖，然后打开浏览器。

双击启动会等待本地服务就绪后打开默认浏览器；如果工作台已经运行，会直接打开已有页面。首次启动的服务窗口需保持打开，关闭窗口或按 Ctrl+C 可停止服务。启动失败时窗口会保留错误提示，详情同时保存到 `logs/launcher.log`。

如果默认浏览器未自动打开，可以手动访问上述地址。若 5173 被其他程序占用，启动器会提示关闭占用程序，不会切换端口，以免看不到原来的本地草稿。

固定使用同一个网址访问：浏览器按“协议 + 主机 + 端口”隔离本地存储，`localhost:5173` 与 `127.0.0.1:5173` 的草稿库不同。

## 使用

1. 点击“导入 Word”选择 `.docx`，或直接把文章粘贴到正文编辑区。顶部“粘贴文章”入口用于把纯文本导入为新草稿。
2. 默认开启“导入后自动美化”：恢复 Word 标题层级，识别代码块、列表和表头，拆分过长段落，并直接展示美化效果。已有草稿点击顶部“一键美化”。
3. 点击“排版样式”，选择七种主题之一。新增“安全研究”“实战教程”“极简长文”，可用当前文章并排对比。在“细节调整”中设置字号、行高、段距、颜色、宋体、首行缩进、章节数字装饰和开篇导读卡片。个人偏好自动记住，新建、Word 导入和粘贴导入会沿用；已有文章保留各自设置。“一键美化”只整理正文结构，不重置样式。
4. 在“原文编辑”中修改标题、列表、引用、链接、表格和图片说明。“撤销美化”恢复本次处理前的正文；继续编辑正文后，使用编辑器的撤销，避免恢复旧快照覆盖新增文字。“查看原稿”保留导入时的快照。原有“整理结构”仍可用于手动确认标题。
5. 点击“复制到公众号”，把带样式的图文粘贴到公众号后台，单独填写文章标题。粘贴后检查图片和最终效果。
6. 打开“我的草稿”切换文章；删除会移入回收站，可以恢复。在“导出”中下载 HTML、备份所有草稿或恢复备份。

文章会自动保存到当前浏览器的 IndexedDB。确认顶部显示“已保存到本地”后再关闭网页。本地排版无需登录；仅主动同步时，通过浏览器扩展把所选图文上传到公众号。远程图片预览会访问其来源网站。

## 阅读密度、自动留白与装饰强度

打开“排版样式 → 阅读节奏”（手机端为“主题与样式”），不必进入细节设置即可调整整篇风格：

| 阅读密度 | 正文行高 | 正文段距 | 适用场景 |
| --- | --- | --- | --- |
| 紧凑 | 1.65 | 12px | 代码较多、信息密集的技术文章 |
| 标准 | 1.8 | 16px | 日常公众号阅读 |
| 舒展 | 2 | 22px | 长文、随笔与需要更多留白的内容 |

- 密度同时调整标题、代码、图片、卡片和表格的留白与内边距，并联动代码行高；保留正文与代码字号、主题色、字体、代码原文及局部设置。选择密度后仍能用“细节调整”微调行高和段距，“已微调”表示当前基于该密度做过修改。行高支持 0.05 精度，紧凑模式的 1.65 不会被滑块四舍五入。
- 默认开启“相邻内容自动留白”：连续标题之间收紧，说明段落贴近后面的代码、图片或表格，新章节前增加间隔；顶层相邻块只保留一次间距，文章末尾不追加空白。列表、引用内部段落使用较小间隔。关闭后恢复各类内容块的固定间距，仍跟随密度缩放。
- 装饰强度分为“简洁 / 适中 / 突出”。简洁使用细线标题、浅色代码、轻量提示卡和表格；适中保留模板原有特点；突出增强章节底色、强调边线和卡片。章节编号、导读开关、代码文件名、强调行与单块换行、图片手动宽度和边框等设置继续有效。
- 点击“对比效果”可用当前文章并排预览三种密度或三种装饰；浏览不会改变文章，点击应用才生效。预览、复制到公众号、HTML 下载和草稿同步使用同一套行内样式；公众号后台可能调整格式，粘贴后检查最终效果。
- 这些设置自动保存，也包含在个人排版方案、历史版本和 ZIP 备份中。旧草稿缺少新字段时使用“标准 + 适中 + 自动留白”，原有的字号、行高和段距保留；切换主题或再次一键美化不会重置阅读风格。

## 开头与文末模板

入口为“排版样式 → 开头与文末模板”，手机端先点“主题与样式”。

1. 点击“新建模板”，填写名称和添加位置；也可从“作者开场 / 关注与交流 / 作者介绍”示例开始。
2. 编辑文字、加粗、列表、链接、分割线与提示卡片，支持粘贴图文、添加本地图片。选中多段内容应用说明、注意等卡片时，整组选区共用一个卡片，保留段落、空行、文字样式和配图；卡片内回车可以继续写下一段，选择“普通正文”可移除卡片。旧模板中每行一个卡片的内容，可重新选中后应用卡片样式并保存。公众号二维码可作为图片加入，选中后调整宽度、对齐和说明。
3. “插入效果预览”展示放入当前文章后的完整效果；“保存模板”存入模板库，“保存并插入当前文章开头 / 文末”同时插入。每套最多 10000 字、20 张图片，最多保存 200 套。
4. 在弹窗顶部，为开头和文末各选择一套自动模板。新建文章、导入 Word、通过“粘贴文章”导入新草稿时，在结构美化完成后自动添加；关闭导入美化时也能添加。新建空白文章时，光标放在开头和文末之间的正文空段。

已存在的草稿通过插入按钮添加，打开或刷新不会自动改动。模板内容会成为文章普通图文，跟随当前主题、阅读密度与装饰设置，可继续编辑、复制、导出和同步。对应开头或文末已经有相同内容时跳过重复添加，包括编辑器补充默认属性、文章前后有空段的情况。修改或删除模板库中的模板不回写已插入的文章；删除自动模板也会取消对应位置的自动添加。

手动插入前保存历史版本，便于恢复；原稿快照保留导入时的内容。导入后撤销美化会保留已添加的开头和文末。个人排版方案原有的“固定文末”继续可用，新模板库提供独立、多套、图文模板与自动添加功能。

ZIP 备份 v3 包含模板、自动添加选择和只在模板中引用的本地图片；恢复创建新副本并重映射图片编号，同名模板另起名称。已有自动选择优先，尚未设置的位置才采用备份中的选择；继续兼容 v1 / v2 备份。

## 历史版本、回收站与个人方案

- 正文上方“历史版本”可以查看时间、保存原因和当时的排版，选中版本后恢复标题、正文与整篇样式。创建或导入时保留一份版本，美化、恢复原稿、应用个人方案、恢复历史版本和移入回收站前留档。编辑自动保存时每 3 分钟最多留档一次，保留的是修改前的内容；也可以手动“保存当前版本”。每篇保留最近 30 份不同内容，连续保存相同内容不会重复占位。
- 历史版本保存在当前浏览器，刷新或关闭后仍可查看；版本里的代码局部设置与图片样式会一并保留。恢复历史版本不会改动最初的原稿快照，恢复前的内容也会留档，便于再找回。
- “我的草稿 → 回收站”可以恢复误删文章，包括正文、原稿、图片、样式及历史版本。不会自动过期。彻底删除需要在回收站内再次确认；删除最后一篇草稿时自动新建空白文章，工作台仍可正常使用。
- “排版样式 → 个人排版方案”可以保存多套命名方案，包含主题、字体、字号、行高、段距、导读、章节装饰、整篇代码及表格设置。支持更新和删除方案；方案不包含正文、图片或单个代码块的局部设置。
- 方案可以附带固定文末；应用时默认只应用样式，勾选后才追加文末。相同文末已位于文章末尾时不会重复添加。应用的样式同时成为新文章的偏好，其他已有草稿保留各自设置。
- 本地自动保存只提交发生变化的草稿，不会因编辑一篇文章而重写其他草稿。旧窗口尝试保存已移入回收站的草稿会停止并提示，避免直接复活已删除内容；当前尚未提供同一篇文章在多窗口同时编辑时的合并功能。
- 新版 ZIP 备份包含草稿、回收站、历史版本、个人方案、开头文末模板和这些内容引用的本地图片；恢复时创建新副本，重映射图片及历史版本编号，同名方案与模板另起名称。继续兼容旧版 ZIP 备份。浏览器数据清除后，本地历史也会被删除，建议定期导出备份。

## 新模板、提示卡片与排版检查

- **安全研究**：分区章节、深色代码、交替底色表格，适合安全分析与验证记录；**实战教程**：圆形步骤编号、浅色代码、暖色导读，适合操作指南；**极简长文**：细线标题与表格、简洁引文、轻量代码标题，适合连续阅读。模板切换保留正文及个人字号、行距等设置。
- “排版样式”根据当前标题与正文推荐版式；点击“用当前文章对比模板”可以并排查看三种完整文章预览，应用后继续调整。推荐使用本地内容规则，无需配置 AI 服务。
- 自动美化识别明确的“说明：”“注意：”“前置条件：”“目标：”“观察：”“修复建议：”等段落，转为对应卡片，保留原文字与强调。没有正文的标签、代码中的字符串、仅在句中提到的词语不会变成卡片；不会补写验证结论。
- 原文编辑工具栏的“提示卡片”可手动选择六种样式。选择“普通正文”会保留取消选择，再次美化也不会自动恢复这张卡片。卡片在预览、复制、HTML、备份与草稿同步中保留对应样式。
- 顶部“排版检查”列出标题跳级、长段落、连续单行代码框、长代码行、被压缩的宽表格，以及本地缺失图片或未填写图片说明。点击问题定位到原文，可整理代码与长段落。检查不会改写文字，也不代替公众号后台预览；远程图片来源是否可访问需在预览中确认。
- 检查分为“需要处理”和“美观建议”：空标题、标题跳级、碎片代码和缺失图片优先显示；段落长度、图注及显示方式为可选建议。建议可逐项忽略并持久记住，展开“已忽略”可恢复提醒；相关内容改变后会重新检查，段落仅移动位置不会重新提醒。明确选择“纯文本”的代码不再提示选择语言。

## 长文与技术文章

- “文章目录”自动收集当前正文中的标题，支持同名章节和层级缩进。点击可定位到编辑器或美化视图；手机端通过目录弹窗跳转。
- 在美化效果中双击正文段落，可定位到原文编辑中的对应位置。美化视图默认收起右侧重复预览，顶部“阅读预览”可随时检查手机和宽屏效果。
- 默认显示编辑与手机预览，主题面板按需展开。“专注模式”收起侧栏；点击“退出专注”或按 Esc 返回。侧栏展开状态和个人偏好保存在当前浏览器。
- “技术手记”使用蓝色章节标题与深色代码卡片。“细节调整 → 代码与表格”可单独设置代码字号和换行；关闭自动换行后，长命令横向滚动，原始文字与换行保持不变。
- Word 导入与富文本粘贴会在解析正文前识别代码，保留原有缩进、Tab、换行和代码内部的空行。支持 Java 对象调用、`adb` / `aapt` 命令及续行、XML / HTML 等技术示例；表格中的短参数、文件名和 URL 使用行内代码，说明文字保留为正文。
- Linux 技术文章支持 `ausearch`、`aureport`、`journalctl`、`crontab`、`last` / `lastb` / `lastlog` 等命令与 auditd 的 `-w` / `-a` 规则。连续命令、注释与内部空行组成完整代码块；syslog、audit 与内核日志以等宽文本展示。命令后的中文解释和选项说明保留为正文，代码示例不会被执行或改写。
- 兼容部分网页编辑器导出的 Word CDATA 文本，避免含 `<`、`>`、`&&` 的 `awk` 等命令被导入库漏掉。此前已导入的文章请重新导入原 Word，以找回导入时遗漏的内容。
- 紧邻对应代码的独立 `bash` 等语言标记移到代码标题栏；单独使用的解释器命令仍然保留。数字步骤使用次级标题，移除空标题；连续的“路径 — 说明”和明确的加粗字段说明整理为列表，正文文件路径使用行内代码。表格内只合并标点、括号与字段等明确的导出碎片，保留独立段落及手动表格结构。
- “原文编辑”工具栏提供“行内代码”和“代码块”，选中代码块后可调整代码语言；代码块内按 Tab 增加四个空格，Shift+Tab 减少缩进。语言用于显示与高亮，不会改写代码。旧版导入已经丢失的缩进无法自动还原，请重新导入原 Word。
- 选中多段正文后点击“代码块”，会合成一个保留换行的代码块。旧草稿中连续的单行代码框可点击“一键美化”合并，保留代码文字和内部空行；说明、标题、图片及完整的多行示例作为边界。代码语言与自动换行设置分别控制高亮和长行显示，不用于合并代码框。
- 表格提供自动、压缩到正文宽度和横向滚动三种显示方式。自动模式在超过三列，或三列中含较长日志/代码示例时保留列宽，支持横向滚动；需要全部列同时显示时选择压缩模式。
- 代码和表格设置统一用于预览、复制、HTML 导出和草稿同步；最终显示仍取决于公众号支持的样式。工作台目录和定位标记不会写入导出或同步正文。

## 局部精修与编辑操作

- 工作台缩小顶部区域与文章标题留白。在桌面端点击“收起预览”可扩大编辑区；拖动右侧预览的左边缘调整宽度，也可选中该分隔条使用左右方向键。宽度与展开状态会记住。手机端通过“正文编辑 / 手机预览”切换视图。
- 在“原文编辑”中点击一段代码，出现“当前代码块”工具。可以单独选择语言、自动换行或横向滚动，添加文件名或示例说明。强调行支持 `2,4-6` 这样的写法，点击“应用”生效；留空后应用可清除强调。设置区可折叠；“恢复整篇设置”清除该块的说明、强调和换行覆盖，保留代码及语言。
- 有局部设置的代码块会保留为独立示例，不会在再次自动美化时被合并。代码的缩进、Tab、空行与原文字保持不变。局部样式用于预览、复制、HTML、备份恢复和草稿同步。
- 点击图片后可调整宽度、左中右对齐、边框或阴影。“替换图片”保留原有图注和显示设置，支持撤销；双击图片或点击“查看大图”查看原图。替换不会修改导入原稿里的图片。
- 插入表格时可选择行数、列数及是否包含表头。从代码中插入表格，会放到完整代码段之后，保留示例连续性。点击表格后，可增删当前行列，拖选多个单元格后合并，或拆分已有合并单元格。手动切换的表头在再次美化后仍然保留；操作支持撤销。

## 同步微信公众号草稿

接入 [Wechatsync / 文章同步助手](https://github.com/wechatsync/Wechatsync) 的浏览器扩展公开 API，建议使用 v2.0.9 或更新版本。账号使用当前浏览器的公众号登录状态，无需填写 AppID、AppSecret 或复制 Cookie。

1. 在日常使用的 Chrome / Edge 中，按项目的[安装说明](https://github.com/wechatsync/Wechatsync#安装方式)安装“文章同步助手”，允许扩展访问本地工作台。
2. 在同一浏览器打开 <https://mp.weixin.qq.com/> 并登录需要接收草稿的公众号。扩展安装后刷新工作台。
3. 完成文章排版后，点击顶部“同步草稿”（或“导出 → 同步到公众号草稿箱”），确认目标公众号和文章标题。
4. 点击“同步到公众号草稿”。工作台核对账号，逐张转存图片，再提交图文。等待显示“已保存为公众号草稿”，点击链接进入公众号检查，补充封面、作者和摘要后再决定发布。

当前只支持在浏览器中登录的公众号，其他平台不会被选中。标题限制为 64 个字；同步使用当前美化样式，标题单独提交，不会因“复制时包含标题”而重复出现在正文。公众号可能进一步处理外链和部分样式，需在后台预览。

每次主动同步新建一份草稿，暂不更新同一篇远端草稿，也不群发或自动发布。图片转存失败时停止提交；页面刷新、关闭或超时后若未收到明确结果，会显示“待确认”，先到公众号后台检查，避免重复创建。同步进行中可收起进度并继续编辑，提交内容使用点击时的快照。

本地保存最近的同步记录和不带登录令牌的草稿地址，不保存公众号 Cookie、AppSecret 或会话 token。同步记录不包含在文章 ZIP 备份中；已同步的远端草稿可在公众号后台管理。详细接口与验证范围见 [接入说明](docs/微信公众号草稿同步.md)。

## 图片、Word 和公众号边界

- 支持 `.docx`，最大 20MB；旧版 `.doc` 需要先另存为 `.docx`。
- Word 转换以文章语义为主，不完整复刻分页、浮动文本框、字体或复杂布局；转换器的警告会在界面展示。
- 本地图片支持 PNG、JPEG、GIF、WebP、BMP 和 AVIF，单张最大 20MB。保留图片在文章里的次序，支持图片说明。
- 公众号复制采用行内样式的 HTML，同时写入纯文本。**复制成功仅表示剪贴板写入成功**，不代表平台已保留所有格式。
- 默认复制包含本地图片的嵌入数据与远程图片链接。平台是否接收图片取决于其编辑器，需在粘贴后确认；若未接收，可导出原图上传，或使用“兼容复制（图片占位）”。远程图片在图片包中提供来源清单。
- HTML 下载会嵌入本地图片，并带有“复制到公众号”按钮，能离线打开查看和复制；远程图片仍依赖其原始链接。浏览器若禁止直接复制，页面会选中正文以便按 Ctrl+C。
- 自动美化使用本地规则，不调用 AI 服务、不改写正文。Markdown 标记和明确的列表符号会转为对应格式。原稿中已经丢失换行的代码保持原样，不猜测或执行代码。
- 草稿同步依赖浏览器扩展与公众号登录状态；微信接口变化可能影响同步。工作台不包含公众号自动发布或群发功能。
- 清除浏览器数据会删除本地草稿、模板和历史版本，建议定期备份。ZIP 备份包含所有文章、原稿快照、主题设置、回收站、历史版本、个人方案、开头文末模板和所引用的本地图片；恢复会创建新副本，不覆盖已有草稿。
- 部署到服务器时请使用 HTTPS。首次安装依赖需要网络；本地排版不依赖在线服务，公众号同步需要联网。

## 构建与验证

### 源码与个人数据

仓库仅包含程序源码、文档及模拟测试样例。个人草稿、图片、模板和同步记录保存在浏览器本地，不随源码上传。`output/`、`logs/`、测试截图、Word 原文、ZIP 备份、数据库和本地凭据已加入 Git 忽略规则；请勿强制提交这些文件。备份和导出文件可能包含完整文章及图片，请自行妥善保存。

本轮功能效果页可用实际 Word 重新生成（使用独立的测试浏览器，不修改日常草稿或原 Word）：

```powershell
node scripts/content-template-showcase.mjs '你的 Word 文章.docx' 'output/开头文末模板预览'
```

该效果页展示模板编辑、自动添加设置以及实际文章的开头和文末；完整 HTML 可以直接复制。脚本使用独立测试浏览器，检查代码、原文、原图、重复插入及模板备份恢复。运行前需启动本地服务。

阅读风格的六种效果可单独生成：

```powershell
node scripts/reading-style-showcase.mjs '你的 Word 文章.docx' 'output/阅读风格优化预览'
```

打开输出目录的 `index.html`，比较同一篇文章的三种密度、三种装饰，以及实际操作截图；六份完整 HTML 都可离线查看和复制。脚本检查原文、代码、原图、样式存储、个人方案、备份恢复、离线复制与窄屏布局。运行前需启动本地服务。

上一轮历史版本、个人方案与回收站的功能效果页仍可单独生成：

```powershell
node scripts/continuity-showcase.mjs '你的 Word 文章.docx' 'output/本轮优化预览'
```

打开输出目录的 `index.html`，可查看历史版本、个人方案、回收站截图和完整排版文章。脚本同时检查代码、原图、备份恢复、离线复制及 390/320px 效果页布局；若已运行浏览器测试，还会附上检查分级的演示文章截图。

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run test:e2e
npm.cmd run test:launcher
```

`build` 执行 TypeScript 检查并生成 `dist/`；`test` 验证内容整理、平台渲染、备份恢复、数据库升级和同步状态处理；端到端测试使用本机 Chrome，覆盖 Word、复制、草稿恢复、同步流程和手机布局。同步测试使用模拟扩展接口，不写入真实公众号。

`test:launcher` 在 Windows 上实际调用 CMD 入口，检查中文及空格路径、重复启动和其他程序占用端口时的处理。

如需用自己的 Word 文件批量验证并生成独立排版示例，先启动开发服务，再运行：

```powershell
node scripts/beautify-samples.mjs '你的 Word 文件夹'

# 可指定输出文件夹与主题：
node scripts/beautify-samples.mjs '你的 Word 文件夹' 'output/技术排版示例' technical

# 为同一篇文章生成三种新版式，附完整 HTML、模板切换预览及六类卡片示例：
node scripts/template-showcase.mjs '你的 Word 文章.docx' 'output/新版排版预览'

# 展示代码局部设置、图片和表格工具，验证并导出可复制的完整文章：
node scripts/refinement-showcase.mjs '你的 Word 文章.docx' 'output/精修排版预览'
```

结果保存到 `output/排版示例/index.html`。使用独立的临时浏览器，不影响日常浏览器的草稿；检查原文、美化后文字、图片嵌入与剪贴板，保留逐篇验证报告。此脚本只访问本地文件和本地工作台。

如需使用 Playwright 自带的 Chromium，可以安装浏览器并将 `playwright.config.ts` 中的 `channel: 'chrome'` 删除。

生产构建预览：

此命令通常使用 4173 端口，其草稿库与 5173 开发端口相互独立。

公众号后台的最终排版、图片转存和真实草稿保存，仍需使用已登录账号验收。
