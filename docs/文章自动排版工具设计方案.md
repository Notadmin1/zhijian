# 文章自动排版工具设计方案

## 1. 产品定位

为个人使用设计的文章排版网页工具。优先接收 Word 文档和粘贴的文章，把内容整理成统一、易读的版式，再复制到微信公众号编辑器发布。

核心流程：**导入或粘贴 → 整理文章结构 → 套用主题 → 局部编辑 → 手机预览 → 复制到公众号**。

第一版采用免登录、本地保存的方式。先验证公众号的实际粘贴效果，再扩展其他平台和自动发布能力。

## 2. 第一版做什么

| 功能 | 第一版范围 | 边界 |
| --- | --- | --- |
| Word 导入 | 支持 `.docx`，提取正文、标题、列表、粗体、图片和简单表格 | 旧版 `.doc` 先提示另存为 `.docx`；复杂文本框、浮动布局等可能需要手动整理 |
| 粘贴文章 | 支持富文本和纯文本；保留文章结构，统一字体、颜色与间距 | 不把来源网页的导航、广告、脚本和全部样式一起搬进来 |
| 自动整理 | 规范空行、段间距，识别已有标题层级、列表和引用 | 对推测出来的标题展示候选，允许确认或撤销 |
| 主题 | 提供 3 套经过验证的主题：简洁阅读、商务专业、温暖随笔 | 优先保证复制效果；不先做大量花哨模板 |
| 手动编辑 | 正文修改、标题层级、加粗、引用、列表、图片说明 | 正文默认左对齐；标题可单独设置对齐方式 |
| 排版设置 | 字号、行高、段间距、主题色、标题样式、图片间距 | 提供有限、可靠的调整项 |
| 预览 | 手机阅读宽度预览；显示字数、预计阅读时长 | 阅读时长是估算；预览不能代替公众号粘贴验证 |
| 发布辅助 | 复制公众号富文本、复制纯文本、下载 HTML | 第一版由用户在公众号后台检查和发布 |
| 本地草稿 | 自动保存、多篇文章管理、修改标题、恢复最近草稿 | 数据只在当前浏览器和设备内保存 |
| 备份 | 导出和恢复包含文章、主题设置与图片的备份包 | 清除浏览器数据会影响本地草稿，需要提供清楚的备份入口 |

暂缓：AI 写整篇文章、自动群发、多用户系统、团队协作、复杂素材库、多平台账号管理。

## 3. 页面怎么安排

采用一个工作台，不需要复杂导航。

```text
┌───────────────────────────────────────────────────────────────┐
│ 草稿列表 / 文章名称     已保存     导入 Word   备份   复制到公众号 │
├────────────┬──────────────────────────────┬───────────────────┤
│ 样式设置    │ 正文编辑区                   │ 手机阅读预览       │
│            │                              │                   │
│ 主题选择    │ 标题                         │ 套用主题后的效果   │
│ 主题色      │ 正文                         │                   │
│ 正文字号    │ 图片与说明                   │                   │
│ 行高/段距   │                              │                   │
│ 标题样式    │                              │                   │
│ 图片样式    │                              │                   │
├────────────┴──────────────────────────────┴───────────────────┤
│ 字数 / 预计阅读时间                         待检查的兼容性问题   │
└───────────────────────────────────────────────────────────────┘
```

桌面宽屏显示三栏；较窄窗口改为“编辑 / 预览”切换，设置面板可以收起。首次打开直接提供“导入 Word”和“粘贴文章”两个入口。

选择主题只改变视觉样式，随时可切换；原文和编辑后的内容都能保留。图片导入未完成时显示进度或失败状态，不能静默丢失。

## 4. “自动排版”具体做什么

### 4.1 内容结构整理

优先使用 Word 或剪贴板里已经存在的语义：标题、段落、列表、粗体、引用、图片、表格。

对于没有结构的纯文本，再用规则给出标题候选，例如“ 一、背景 ”、“ 01 项目介绍 ”。规则综合段落长度、编号形式和上下文，不把所有短句自动改成标题。

结构整理遵循以下原则：

- 默认不改写正文，不增删观点，不擅自变更标点和数字。
- 清理多余空行、空段落和来源样式，保留有意义的段落分隔。
- “整理结构”作为可撤销操作，展示识别结果；重复执行不应不断改变文章。
- 首段不一定是文章标题；无法确定时由用户指定。
- 文章标题单独保存，复制时默认只复制正文，方便填入公众号独立的标题栏；提供包含标题的选项。

### 4.2 视觉排版

第一套默认参数可从下表开始，通过真实粘贴效果微调：

| 元素 | 建议默认值 |
| --- | --- |
| 正文 | 16px、行高 1.8、深灰色、左对齐 |
| 段落 | 段后间距 16px，默认不首行缩进 |
| 一级小标题 | 20px、加粗，明显的段前间距 |
| 二级小标题 | 18px、加粗，适量段前间距 |
| 引用 | 浅色背景或左侧色条，保留文字本身的可读性 |
| 图片 | 按正文宽度缩放，不拉伸，提供图片说明 |
| 说明文字 | 13px、灰色，与图片保持合适距离 |

内部主题通过设计变量控制，界面预览可以使用 CSS 变量；导出时转成目标平台适用的具体行内样式。

## 5. 推荐技术方案

第一版做成本地优先的 Web 应用，普通电脑浏览器即可使用。无需先准备服务器、数据库或公众号开发者账号。

| 部分 | 推荐选择 | 用途 |
| --- | --- | --- |
| 页面与交互 | React + TypeScript + Vite | 构建工作台、设置面板和预览 |
| 正文编辑 | Tiptap / ProseMirror | 提供结构化富文本编辑与撤销能力 |
| Word 解析 | Mammoth | 将 `.docx` 提取为可整理的 HTML 和图片 |
| 输入清理 | DOMPurify + 受控解析规则 | 移除危险内容，整理粘贴和导入结果 |
| 本地存储 | IndexedDB，使用 Dexie 简化操作 | 保存草稿、图片 Blob 和历史快照 |
| 备份打包 | ZIP 工具，例如 JSZip | 导出文章数据与图片资产 |
| 排版导出 | 自建受控渲染器 | 从结构化正文生成公众号适配的 HTML |

第一版不需要独立后端。如果后续增加 AI、跨设备同步或公众号接口，再增加后端处理密钥、鉴权和任务；密钥不能直接放在前端。

### 5.1 数据流

```text
Word 文件 ── Mammoth ──┐
                      ├─ 输入清理与语义转换 ─ 统一正文 JSON
粘贴文本 / HTML ───────┘                         │
                                                ├─ 编辑器与自动保存
主题变量 + 局部样式覆盖 ───────────────────────────┤
                                                └─ 平台渲染器
                                                     │
                                   预览 / 剪贴板 HTML / HTML 文件
```

不要直接复制编辑器 DOM。编辑器的界面结构和平台可接受的文章结构不同，预览与导出应复用同一套平台渲染规则。

### 5.2 核心数据

以编辑器 JSON 作为正文的唯一编辑数据源，至少支持：段落、标题、粗体、斜体、链接、列表、引用、分隔线、图片、图片说明、简单表格。

文章保存以下信息：

- `id / title / createdAt / updatedAt`：草稿基础信息。
- `schemaVersion`：数据结构版本，方便以后迁移。
- `document`：当前可编辑的结构化正文。
- `themeId / themeOverrides`：主题和全局参数覆盖。
- `platform`：当前预览与导出的目标平台，第一版为微信公众号。
- `assetIds`：正文引用的图片资产。
- `sourceSnapshot`：导入时的内容快照，用于找回原文。

图片独立保存为资产，通过稳定的 `assetId` 引用。`blob:` 地址只是当前会话的预览地址，重新打开草稿时重新生成，不能作为持久图片地址或可发布地址。

Word 导入是一次性转换，不要求导回 Word，也不要求完整复刻 Word 页面的版式。

## 6. 公众号适配是最关键的工程部分

### 6.1 文字与样式

- 使用经验证的 HTML 元素和行内样式，避免依赖外部样式表。
- 正文结构保持简单，不依赖脚本、悬浮交互或复杂页面布局。
- 通过平台渲染器约束样式范围；平台可能重新处理标签和样式，需要实际粘贴验证。
- 复制时同时提供 `text/html` 和 `text/plain`，使用浏览器剪贴板能力；界面保留失败提示与可用的手动复制途径。
- 开发环境使用 localhost，部署后使用 HTTPS，并优先验证 Chrome / Edge。
- “已复制”只表示写入剪贴板成功，不能表示公众号已完整接收。

### 6.2 图片

图片必须单独设计，不能把“编辑区能看见”当作“公众号能发布”。

1. Word 内嵌图片提取到本地素材存储，保留其在文章中的位置。
2. 粘贴的图片文件可保存为本地资产；远程图片可能受到来源防盗链或跨域限制，不能假设都能下载。
3. 本地 Blob 地址和任意 Base64 图片不作为公众号可发布图片的保证。
4. 复制前显示待处理图片数量；无法可靠复制的图片保留清楚的占位和说明。
5. 提供按文章顺序导出图片的方式，用户可在公众号后台逐张上传并替换占位；有图正文不应在无提示的情况下“成功导出”却缺图。

后续如果账号权限和官方接口允许，可增加素材上传或草稿同步。该路线依赖实际账号资格、授权和最新接口规则，作为单独阶段验证，不承诺所有公众号都能直接接入。

### 6.3 表格与特殊内容

第一版支持简单表格并提示检查宽度。复杂表格、公式、代码块等保留内容，并根据目标平台提示调整或转换。转换为图片会影响复制、检索和后续编辑，应作为明确选择。

其他平台以后各自增加渲染器，不默认认为公众号输出能够直接适用于所有平台。

## 7. 实施顺序与验收

### 阶段一：打通最小链路，优先验证复制能力

实现文章粘贴、基础富文本编辑、1 套主题、手机宽度预览、复制公众号正文。

用一篇包含二级标题、正文、粗体、列表和引用的真实文章，在公众号后台粘贴检查。若主要样式被过滤，先调整渲染规则，再扩展主题。

### 阶段二：支持日常输入和稳定保存

加入 `.docx` 导入、标题候选整理、图片提取、多篇草稿、自动保存和备份恢复。

检查 Word 的内容顺序、中文文字、列表层级、图片位置；刷新或关闭重开后能恢复正文和图片。保存失败应明确提示，不能继续显示“已保存”。

### 阶段三：打磨使用体验

补齐 3 套主题、局部样式设置、字数和阅读时间、HTML 下载、图片导出、兼容性提示。

完成后再评估是否需要 AI 辅助或平台接口，不为了未来功能提前建设账号和服务端。

实际开发量需要在编辑器与公众号复制验证后细化，优先按可用成果拆分，避免先承诺固定工期。

### 第一版的关键验收场景

| 场景 | 通过标准 |
| --- | --- |
| Word 导入 | 正文顺序和文字保留，标题/列表可编辑，图片位置可确认；不支持的内容有可见提示 |
| 粘贴来源文章 | 文章内容保留，来源字体和颜色被主题统一，脚本等无关内容被清理 |
| 标题整理 | 识别结果可检查、可撤销；正文不会被静默改写 |
| 主题切换 | 切换主题不丢正文，返回原主题时结果稳定 |
| 公众号粘贴 | 在实际后台检查标题、段距、行距、引用、列表；正文文字和次序一致 |
| 图片导出 | 无法发布的图片有提示，可以按正文顺序导出并手动替换 |
| 草稿恢复 | 同一浏览器重开后能恢复；备份包能恢复正文、主题和图片 |
| 长文章 | 使用约 2 万字和多张图片的样例，检查输入、预览、保存是否明显卡顿 |

自动化测试重点放在导入转换、内容不丢失、平台渲染和备份往返恢复。平台粘贴效果仍需在真实编辑器里人工验收。

## 8. 后续可增加的功能

- 保存个人常用主题、落款、关注引导与文章尾部信息。
- AI 推荐标题层级、摘要和重点句，先展示建议，再由用户应用；改写与纯排版作为不同操作。
- Markdown 导入和导出。
- 跨设备同步和素材管理。
- 经账号能力验证后的公众号草稿同步。
- 增加其他平台导出规则及其独立验收样例。

建议从“粘贴正文 → 一套主题 → 公众号实际粘贴”开始验证，然后做 Word 导入和本地草稿。这条顺序能够尽早确定工具最重要的能力是否可靠。
